#1

공중 체리가 뒤쪽 타일 위에 있는 것처럼 보임

게임해결
증상
구멍 (1,2) 위 1.8m에 떠 있는 체리가 쿼터뷰에서는 뒤쪽 타일 (1,3) 위에 놓인 것처럼 보였습니다.
원인
높이 단서가 없는 공중 물체는 고정 쿼터뷰에서 깊이를 알기 어렵습니다. 체리 그림자도 뒤쪽 타일에 떨어져 착시를 키웠습니다.
해결
공중 체리의 그림자를 끄고, 구멍 속까지 내려가는 반투명 빛기둥을 추가했습니다 (ItemSetup).
교훈
쿼터뷰에서 공중에 두는 물체에는 수직 기준선(빛기둥, 그림자 등)을 붙입니다.
#2

공중 체리를 먹고 클리어되면 조작이 잠겨 구멍에 빠짐

게임해결
증상
마지막 체리가 구멍 위 공중 체리이면, 먹는 순간 클리어 → 조작 잠금 → 수평 이동이 멈춰 여우가 구멍으로 떨어졌습니다.
원인
조작을 잠글 때 공중에서 하던 이동까지 멈췄습니다.
해결
FoxController.InputEnabled가 꺼져도 공중에서는 하던 이동을 이어 가 착지하게 했습니다 (carriedDir). 착지한 뒤에 멈춥니다.
검증
ResultSetup "전부 수집 → 클리어" (여우가 건너편에 착지)
#3

fps가 아주 높으면 여우가 움직이지 않음

테스트해결
증상
Play 모드 테스트를 배치 모드로 돌리면 W를 눌러도 여우가 움직이지 않았습니다.
원인
배치 모드는 프레임당 0.0001초 수준이라 한 프레임 이동량이 CharacterController.minMoveDistance(기본 0.001m)보다 작아 무시됐습니다.
해결

교훈
편집 모드 시뮬레이션만으로는 못 찾는 문제가 있어 Play 모드 테스트도 함께 돌립니다.

#8

WebGL에서 결과 화면 한글이 안 보임

빌드해결
원인
ResultScreen이 Font.CreateDynamicFontFromOSFont로 맑은 고딕을 불러왔는데, 브라우저에서는 OS 폰트를 쓸 수 없습니다. 기본 LegacyRuntime.ttf에는 한글이 없습니다.
해결
PC에 있던 Noto Sans KR(SIL OFL, 배포 가능)을 Assets/Resources/Fonts/NotoSansKR.ttf에 넣고, Resources.Load로 먼저 쓰게 했습니다. 폰트가 없으면 OS 폰트를 씁니다. 라이선스 파일도 함께 넣었습니다.
주의
맑은 고딕 같은 Windows 폰트는 재배포 라이선스가 없어서 게임에 넣으면 안 됩니다.
비용
폰트 약 10MB가 빌드에 들어갔습니다 → #12에서 쓰는 글자만 남긴 서브셋(75KB)으로 바꿨습니다.

#11

WebGL에서 타일·여우·체리가 안 보임 (그림자 샘플러 형식 불일치)

빌드해결
증상
브라우저에서 HUD, 반투명 그림자, 빛기둥만 보이고 URP Lit 물체가 전부 사라졌습니다. 콘솔에 경고가 가득했습니다.
GL_INVALID_OPERATION: glDrawElements: Mismatch between texture format and sampler type (signed/unsigned/float/shadow)
찾은 방법
  • 브라우저에서 WebGL2 drawElements를 가로채, 실패한 호출마다 셰이더의 샘플러와 실제로 묶인 텍스처 형식을 기록했습니다.
  • hlslcc_zcmp_AdditionalLightsShadowmapTexture가 sampler2DShadow인데, 묶인 텍스처는 16×16 SRGB8_ALPHA8이었고 비교 모드도 꺼져 있었습니다.
  • 그 자리에 메인 그림자 맵(깊이 텍스처)을 임시로 넣어 보니 오류 0건에 화면이 정상이 됐습니다 → 원인 확정.
원인
WebGL은 Mobile 품질(Mobile_RPAsset)을 씁니다. 이 설정은 추가 조명 그림자가 꺼져 있어서, URP가 추가 조명 그림자 맵 자리에 일반 컬러 텍스처를 묶었습니다. 그런데 Lit 셰이더는 여전히 그 텍스처를 그림자 샘플러로 읽습니다. WebGL2는 형식이 맞지 않으면 그리기를 거부합니다. 에디터(PC 품질, D3D11)에서는 드러나지 않았습니다.
해결
Mobile_RPAsset의 m_AdditionalLightShadowsSupported: 1. 추가 조명이 없어 비용은 거의 없습니다.
교훈
  • 플랫폼마다 쓰는 품질 설정이 다릅니다 (QualitySettings의 m_PerPlatformDefaultQuality: WebGL → Mobile). 에디터에서 된다고 빌드에서 되는 것은 아닙니다.
  • WebGL은 빌드한 뒤 브라우저 콘솔의 GL 경고까지 확인합니다.
#12

WebGL 빌드 용량이 큼 (약 63MB)

빌드해결
내용
WebGL.wasm 46MB, WebGL.data 19MB. 첫 로딩이 오래 걸렸습니다.
먼저 확인
  • GitHub Pages가 이미 gzip으로 보내고 있어서, 실제로 받는 양은 약 22MB였습니다 (Content-Encoding: gzip).
  • BuildPlayerOptions에 Development 옵션을 주지 않으므로 개발 빌드는 아니었습니다(처음의 추정이 틀림).
  • 빌드 보고서를 보니 data의 절반 이상이 한글 폰트(9.9MB)였습니다.
해결
WebGLBuild가 빌드 때마다 자동으로 적용합니다.
  • 한글 폰트 서브셋 (Assets/Editor/FontSubsetter.cs): 원본 가변 폰트는 빌드에 안 들어가는 FoxGame/FontSource/로 옮기고, C# 파일에 나오는 글자 + ASCII만 남긴 TTF를 Resources에 만듭니다 (508자, 9.9MB → 75KB). 문구를 바꿔도 빌드 때 다시 만들어집니다.
  • 코드 최적화 DiskSizeLTO (리플렉션으로 설정)
  • 코드 제거 ManagedStrippingLevel.High
결과
원래 크기받는 양(gzip)
전62.8MB21.8MB
후37.5MB13.2MB
wasm 44.4 → 27.7MB, data 17.9 → 9.4MB · GitHub Pages 실측(gzip 전송): wasm 9.2MB + data 4.7MB ≈ 13.9MB
확인
브라우저에서 이동, 체리 먹기, 점프, 무너지는 바닥, 한글 GAME OVER 화면, Enter/R 재시작 모두 정상, 콘솔 오류 0건
주의
  • 코드 제거 High에서 리플렉션으로만 쓰는 코드가 빠질 수 있습니다. 새 패키지를 넣으면 WebGL에서 꼭 확인합니다.
  • LTO 때문에 빌드가 오래 걸립니다(약 13분).
  • 로딩 직후 몇 초는 끊길 수 있습니다. 확인할 때는 조금 기다린 뒤 조작합니다.
남은 후보
Unity 스플래시 화면 끄기(로고 텍스처 2.7MB). "Made with Unity" 표시를 없앨지는 사용자가 정할 일입니다. 후처리 텍스처는 #22 참고.
#13

에디터가 프로젝트를 열고 있으면 배치 모드 검증을 돌릴 수 없음

도구우회 중
원인
Unity는 같은 프로젝트를 두 인스턴스가 동시에 열 수 없습니다.
우회

  • -executeMethod VerifyAll.Run / -runTests -testPlatform PlayMode
  • 통과를 확인한 뒤, 씬을 바꾸는 셋업은 사용자가 에디터 메뉴로 실행합니다.
참고
복사본 로그의 Library\PackageCache ... DirectoryNotFoundException 오류는 복사한 패키지 캐시 경로 문제이고, 검증 결과와는 관계없습니다.

#15

기존 전체 코스 검증 경로가 무너지는 바닥 규칙과 맞지 않음

테스트정리
내용
ItemSetup · ResultSetup의 "전체 코스" 경로는 같은 타일을 다시 지나갑니다. 무너지는 바닥 규칙에서는 불가능한 경로입니다.
처리
이 시뮬레이션들은 TileCrumbler를 돌리지 않아, 무너짐 없이 체리 · 결과 로직만 확인하는 검증으로 그대로 둡니다. 새 규칙에서의 클리어는 CrumbleSetup의 "무너지는 바닥으로 전체 코스 클리어"에서 다른 경로로 확인합니다.
주의
레벨 배치(LevelLayout.Rows)를 바꾸면 CrumbleSetup의 클리어 경로도 다시 확인해야 합니다.

원인

#26

서명 안 된 MSIX는 이 PC에 바로 설치해 볼 수 없음

배포사용자 작업
내용
스토어에 올리는 MSIX는 서명 없이 올리면 스토어가 서명합니다. 하지만 로컬에서 설치해 보려면 서명과 인증서 신뢰가 필요합니다.
처리
인증서를 신뢰 저장소에 넣는 것은 보안 설정 변경이라 자동으로 하지 않았습니다. 대신 exe를 직접 실행해 확인했습니다.
직접 해 보려면
  • 자체 서명 인증서(New-SelfSignedCertificate, Subject는 publisher와 같은 CN) → signtool sign /fd SHA256 → 인증서를 "신뢰할 수 있는 사람"에 넣고 MSIX 설치
  • 또는 개발자 모드에서 Add-AppxPackage -Register FoxGame/Builds/Store/layout/AppxManifest.xml
